# ADR 0024 — Internationalisation Qt Linguist

- **Statut :** accepté
- **Date :** 2026-09-04
- **Phase :** post-21 (§44)

## Contexte

Le cahier demande que tout texte utilisateur passe par `tr()`, et un pipeline Linguist (`.ts` / `.qm`) **sans bloquer** le reste du produit. Le baseline listait `FindReplaceDialog`, la typo « Show lignes », et l’absence de catalogues.

## Décision

- Chaînes UI en `tr()` (Find/Replace, `.ui`, messages de tâches visibles). Source **anglais**.
- Catalogues versionnés : `translations/editerako_en.ts`, `translations/editerako_fr.ts`. `lrelease` au build (`qt_add_translations`) ; `lupdate` **manuel** (`ninja update_translations`) pour ne pas saloper git à chaque compile.
- `.qm` embarqués sous `:/i18n`. `TranslationLoader` charge `qtbase` + `editerako_<lang>` selon `ui/language` (vide = locale système). La langue choisie dans Préférences s’applique au **lancement suivant**.
- Tests : mapping locale / présence des traductions Find/Replace dans le `.ts` français. Pas un `tr()` par chaîne.

## Conséquences

- LinguistTools (`lupdate` / `lrelease`) est dans l’archive Qt de base `qttools`, déjà fournie par aqt. Ne pas demander `qttools` ni `qtsvg` via `-m` (modules extra inexistants → aqt exit 1). Le seul extra CI est `qtpdf`.
- Un `.ts` français incomplet affiche l’anglais pour les chaînes non traduites.
